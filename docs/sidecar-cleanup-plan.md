# 方案：复制到 exFAT 后清理 4KB 的 `._` 文件

日期：2026-11-19　状态：已实现并通过 review，尚未提交

## 1. 问题

从 Mac 复制到 exFAT 硬盘后，目标盘上每个文件和文件夹旁边都多出一个 4KB 的 `._同名` 文件。在 Windows 上这些文件全部可见。

现有的排除规则（`--exclude "._*"`）只是不复制**源盘里已有**的 `._` 文件，挡不住**目标盘上新生成**的。

## 2. 原因（已在临时 exFAT 镜像上实测）

用应用实际使用的参数（`--check-first --local-no-clone` 加排除规则）、rclone 1.76.0 复制 3 个文件加 1 个子文件夹：

| 操作 | 目标盘上的 `._` 文件 |
|---|---|
| 首次复制 | 5 个：每个文件 1 个、子文件夹 1 个、目标文件夹本身 1 个（在它的上一级） |
| 只读、列目录、`rclone check --size-only` | 不生成 |
| 全部删掉后再跑一次复制（没有新文件） | 4 个，全部回来 |
| `xattr -d com.apple.provenance` | 命令成功，但 `._` 文件还在 |
| 直接删除 `._` 文件 | 删掉后不再回来，文件内容逐字节一致 |

结论：

- **不是 rclone 带过去的**。源文件上的隔离标记和 Finder 标签都没有出现在目标盘。
- **是 macOS 自己加的**。`._` 文件里只有 `com.apple.provenance` 一个属性。系统给进程写入或修改的每个文件打这个标记，exFAT 存不了扩展属性，就落成 4096 字节的 AppleDouble 文件。
- **应用内无法阻止**，只能事后删除。
- **重跑会再生成**。exFAT 的修改时间精度是 10 毫秒，APFS 是纳秒，rclone 每次都判定时间不一致：先对两边各算一遍 MD5，再重写目标的修改时间，系统于是再打一次标记。

没有验证的部分见第 8 节。

## 3. 目标

- 一次正常复制结束后，目标文件夹里不留下由这次（或以前）复制产生的 `._` 文件。
- 不丢任何有用的元数据：带 Finder 标签、资源分支、隔离标记等内容的 `._` 文件一律保留。
- 目标是 APFS、HFS+ 这类原生支持扩展属性的磁盘时，完全不做任何额外操作。

不在范围内：

- `.DS_Store`。它是 Finder 浏览目标盘时生成的，和复制无关。
- 目标盘上与本路线无关的其他文件夹。
- 源盘。

## 4. 方案 A：复制后清理（主体）

### 4.1 什么时候运行

同时满足以下条件才运行：

1. 是真实复制，不是预演。
2. rclone 复制正常结束（退出码 0）。
3. 路线的“清理 `._` 文件”选项开启（默认开）。
4. 目标卷不原生支持扩展属性。用 `getattrlist` 读卷能力里的 `VOL_CAP_INT_EXTENDED_ATTR` 位判断。实测 exFAT 镜像返回不支持，APFS 返回支持。

中断或失败的运行不清理。下次成功运行会扫描整个目标文件夹，一并清掉。

### 4.2 删哪些

对目标文件夹里每个名字以 `._` 开头的条目 `._X`，同时满足才删除：

1. `._X` 本身是普通文件，不是符号链接或文件夹。
2. 同一文件夹里存在 `X`（文件或文件夹）。
3. `X` 的扩展属性列表**恰好只有** `com.apple.provenance`。

其余一律保留：

| 情况 | 处理 | 原因 |
|---|---|---|
| `X` 还带 Finder 标签、资源分支、隔离标记等 | 保留 | 里面有用户可能在意的数据 |
| 没有对应的 `X`（孤立的 `._` 文件） | 保留 | 无法判断来源 |
| `._X` 不是 AppleDouble，只是名字碰巧 | 保留 | 这时 `X` 没有任何属性，条件 3 不成立 |

实测带标签的文件属性列表是 `com.apple.provenance` 加 `com.apple.metadata:_kMDItemUserTags`，能和“只有 provenance”区分开。

没有采用 `dot_clean -m`：它不看内容，会把带标签和资源分支的 `._` 文件也一起删掉。

### 4.3 扫描范围

- 每个实际写入的目标文件夹（`TransferTask.copyPairs` 里的 `destination`），递归扫描。
- 另外检查每个目标文件夹自身的 `._<文件夹名>`，它在上一级目录里。只在目标文件夹不等于所选目标位置时检查。

“合并”布局下目标文件夹可能是一个已有很多内容的文件夹，这时会整个扫描。因为删除条件是无损的，顺带清掉旁边的 provenance 标记文件没有副作用，代价只是扫描时间。

### 4.4 流程位置

```text
预检查 → 复制 → 清理 → （可选）校验 → 完成
```

放在校验之前：只需要在 `finishCopy` 成功分支加一个入口，而且校验看到的是磁盘的最终状态。实测校验不会让 `._` 文件再生成。

- 新增状态 `cleaning`，文案“清理中”。
- 清理期间点“停止”：立刻停下，本次运行记为已完成，提示“复制已完成，清理已中断”。
- 清理出错（个别文件删不掉、磁盘被拔出）不改变复制结果，只在结果里说明。

### 4.5 安全

- 开始前重新校验目标路径快照（`DestinationPathPolicy.validate`），和校验步骤相同。
- 遍历时不跟随符号链接，不跨越挂载点（比较 `st_dev`）。
- 只对名字以 `._` 开头的普通文件执行 `unlink`，删除前再 `lstat` 一次。
- 全程在后台线程运行，不阻塞界面。

### 4.6 界面

- “高级”弹窗里加一个勾选项：**清理 macOS 生成的 `._` 文件**，默认开。说明文字：“复制到 exFAT、FAT 这类磁盘时，macOS 会给每个文件附带一个 4KB 的 `._` 文件。开启后复制完成时自动删除，带标签等信息的不删。”
- 结果文案：`复制完成，已清理 1,234 个 ._ 文件。` 没有可清理的就保持现在的文案。
- 目标是 APFS 等磁盘时不显示任何清理相关的信息。

## 5. 方案 B：重跑时不再重写时间（建议单独提交）

排查时发现的相关问题：目标是 exFAT 时，每次重跑都会对所有已存在的文件两边各算一遍 MD5，源在网络共享上时等于把所有内容重读一遍。

实测，对已经复制完的目标再跑一次：

| 参数 | MD5 次数 | 文件时间重写 | 重新生成的 `._` |
|---|---|---|---|
| 现状 | 3 | 3 | 4 |
| `--modify-window 1s` | 0 | 0 | 1（子文件夹） |
| `--modify-window 1s --no-update-dir-modtime` | 0 | 0 | 0 |

建议：目标卷类型是 `exfat` 或 `msdos` 时给 `rclone copy` 加 `--modify-window 2s`（FAT32 的时间精度是 2 秒）。不加 `--no-update-dir-modtime`，否则文件夹的修改时间不再保留，剩下的那个由方案 A 清理。

这是独立的性能修复，不做也不影响方案 A。

## 7. 测试与验证

**单元测试**（`SidecarCleanerTests.swift`，属性读取做成可注入，在普通临时目录里就能跑）：

- 只有 provenance 的被删除；带标签的保留；孤立的保留。
- `._X` 是符号链接或文件夹时保留；不进入符号链接指向的文件夹。
- 文件夹的 `._` 文件、多层嵌套、目标文件夹自身的 `._` 文件。
- 停止标志生效；删除失败计入失败数而不抛出。
- 旧版路线存档解码后 `cleanSidecars` 为 `true`。
- 方案 B：`--modify-window` 只在 `exfat`、`msdos` 目标时出现。

**集成测试**：用 `hdiutil` 建一个小的 exFAT 镜像（不需要管理员权限），真实跑 rclone 复制再清理，确认 `._` 文件归零、带标签的保留、内容一致。镜像建不出来或运行环境不产生 `._` 文件时跳过。

**合并前在真实应用里验证**：

1. 构建并运行应用，把一个 Mac 文件夹复制到 exFAT 镜像，确认结果文案和 `._` 文件数为 0。
2. 给目标盘上一个文件打 Finder 标签后再跑，确认它的 `._` 文件保留。
3. 关闭勾选项再跑，确认 `._` 文件留在原处。
4. 开启“复制后校验”、多文件夹路线、“合并”布局各跑一次。
5. 清理过程中点停止。
6. 目标换成 APFS 文件夹，确认没有清理步骤。
7. 在真实的 exFAT 硬盘上跑一次，并记录清理耗时。

## 8. 尚未验证

- **清理过程中点停止或退出应用**。只读过代码，没有实际操作过（小镜像上清理只需几毫秒，来不及点）。
- **界面文案**。应用内实测是通过运行结果和磁盘上的文件确认的，没有看界面截图。

实现后已在应用内实测（临时 exFAT 镜像）：首次复制后 `._` 文件为 0；带标签的保留；关闭选项后 5 个全部留下；开启校验后结果为“已完成并校验”；APFS 目标正常完成。
- **网络共享（SMB、NAS）目标**。卷能力位在这类目标上的取值没有测过。
- **FAT32**。只测了 exFAT。
- **大盘上的清理耗时**。每个文件夹读一次目录，每个 `._` 候选读一次属性，没有在真实硬盘上测过。

## 9. 已确认的决定（2026-11-19）

| 问题 | 决定 |
|---|---|
| 清理选项默认开还是关？ | 默认开。已保存的路线升级后也会自动清理 |
| 方案 B 要不要一起做？ | 一起做 |
| 中断或失败的运行要不要也清理？ | 不清理，留给下次成功的运行 |
